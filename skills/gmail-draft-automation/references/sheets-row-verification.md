# Sheets 행 자동 매칭 검증 — 스크립트가 잡은 행을 그대로 믿지 않는다

자동 매칭이 시트 행을 골랐다는 로그(`[매칭성공]`, `[블록확정] …행합계 N원`)는 **증거가 아니라 주장**이다.
확정 전에 아래 세 가지를 직접 대조한다. 하나라도 어긋나면 초안·시트 모두 손대지 않는다.

## 왜 이 검증이 필수인가

OCR/LLM 파이프라인이 타임아웃으로 소실되면 품목 정보가 **파일명 토큰**으로만 남는다
(로그에 `[매칭방식] 파일명 대표품목 기준`으로 찍힘). 이 상태의 매칭은 시트를 훑다가 무관한 행을 집을
확률이 높다. 관측된 실패 사례:

- 시트 지정 없이 실행 → `그룹과제_예시` 110행. 실제 내용은 `Example Ab CAT-0003 Anti-4 Hydroxynonenal
  antibody`(ferroptosis 연구용) — 대상 품목과 무관. 단가/금액 셀이 비어 있어 **행합계 0원**.
- `--sheet-name PROJECT_2026`로 재실행 → 163행 `Example Bio CAT-0002 Target-G Recombinant Rabbit Monoclonal
  Antibody` (649,000원). 대상은 689,700원으로 **금액까지 다르다**.
- 정답은 189행 `Example Chemicals CAT-0001 Anti-Target-B Antibody, clone 6C4` / 627,000 / 689,700.

**`--sheet-name` 지정은 해결책이 아니다.** 오매칭된 다른 행을 집을 뿐이다.

## 검증 3항목

1. **품목 일치** — 선택 행의 `Cat. No` / `제품명`이 해당 거래명세서 품목과 일치하는가. 가장 빠르고 확실하다.
2. **금액 일치** — 블록 행합계가 세금계산서 합계와 일치하는가 (±1원 또는 천원 반올림 허용).
   **`행합계 0원`은 절대 매칭 성공이 아니다** — 단가/금액 셀이 빈 행이 잡힌 경우다.
   시트 금액 셀(헤더 `금   액`)이 비어 있으면 즉시 실패로 본다.
3. **공급자 확인** — `[세금계산서] … / 공급자 미추출` 상태로 확정되지 않았는가.
   공급자는 시트 `Vendor` 열(헤더 `Vendor`)과 부분 일치 비교한다.

실패 시 로그에 원인을 남긴다:
`[매칭실패] 블록합계 649,000원 ≠ 세금계산서 총액 689,700원 (행 163: Target-G …)`

## 정답 행을 직접 찾는 방법

전체 시트를 품목명 + 금액으로 훑는다. 시스템 시트(`CONFIG`, `업체정보`, `분개원장`, `예산_설정`,
`로그`, `메일로그`, `견적수신`, `견적비교`, `결제처리`)는 제외한다. 거래명세서 합계와 정확히 일치하는
행을 찾으면 그게 정답이다 — 실제로 이 방법으로 189행을 찾아 초안을 정상 생성했다.

```python
for row in rows:
    if key not in line:
        continue
    amount = (row[9] if len(row) > 9 else "").strip()   # 헤더 '금   액'
    if amount == expected_total:
        print(sheet, idx + 1, line)
```

## 기안일에 넣을 날짜

**전자세금계산서 작성일자**를 쓴다(파일명 날짜·거래명세서 날짜로 대체 금지). 둘은 다를 수 있다
(파일명 8/13, 세금계산서 10/1). 시트 헤더 `기안일`에 기록하며, `지급일`/`지급상태`/`마지막처리일시`
헤더가 없는 시트에서는 `기안일`만 기록되는 것이 정상일 수 있으니 쓰기 전 헤더 존재를 확인한다.
