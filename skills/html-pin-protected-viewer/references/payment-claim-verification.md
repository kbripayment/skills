# 지급신청(지급승인) 서류 검증 — 종료까지 절차

전자세금계산서 확보 이후 단계. `apply_payment_skill.py`는 자동화일 뿐 최종 판단은
사람이 하므로, 아래 순서를 지키면 "초안은 들어갔는데 엉뚱한 시트 행을 찍었다" 류의
사고를 막을 수 있다.

## 버그 발견 시 기록 위치 규칙

`automation/scripts/requirement_automation.md` 는 **요구사항 문서**다. 담는 것은
버그 발견 사실 · 원인 · 요구사항 항목 · 회귀 기준뿐이고, 담지 않는 것은 다음과 같다.

- 실행 로그 원문, 개별 파일명·시트 행·금액 등 개별 사안 데이터
- 수동 처리 내역·실행 결과 보고

**개별 사안은 코드가 이미 수정 중이거나 요구사항 본질과 무관하면 올리지 않는다.** 올리면
다음 작업자가 출처를 추적하지 못하고, 회귀 테스트에 재사용되지 않은 수치가 dead data로
남는다. 요구사항이 아니라면 `scripts/progress_automation.md` 가 구현 내역의 자리다.

회귀 기준은 개별 사안 설명 대신 **코드 블록에 값만** 남긴다 — 수정자가 그대로 테스트
케이스로 복사할 수 있어야 한다.

## 0. 항상 `--dry-run`부터

```
python scripts/apply_payment_skill.py "<품목명>" --folder "Y:/" --project-code <코드> --dry-run
```

dry-run은 초안·시트에 아무것도 쓰지 않는다. **로그를 읽고 판단한 뒤** 실실행한다.

## 1. dry-run 로그에서 3가지를 확인

| 로그 | 정상 | 위험 신호 |
|---|---|---|
| `[매칭시도]` | 견적서 기준 / 세금계산서 기준 | `파일명 대표품목 기준` 만 남으면 품목 정보가 LLM 단계에서 소실된 것 |
| `[블록확정]` | 행합계 == 세금계산서 총액 | `행합계 0원`, 또는 총액과 다른 금액 |
| `[초안] 제목` | 금액이 세 자리 콤마 포함 | `금액미확인`, `_원` (금액 누락) |

`[실패] … 서명검증(금액·품목·공급자) 미통과` 로 끝나면 **막힌 것이 아니라 막아낸 것**이다.
스크립트를 고쳐 억지로 통과시키지 말고, 아래 2번부터 수동으로 확정한다.

## 2. 시트 행을 독립적으로 대조 (스크립트 판정을 믿지 않는다)

dry-run이 "매칭성공"을 찍어도 실제 행이 맞는지 확인한다. 품목명만이 아니라
**금액으로** 찾는다:

```python
for sh in target_sheets:
    vals = sheets.values().get(spreadsheetId=SID, range=f"'{sh}'!A:Z",
                               valueRenderOption="FORMATTED_VALUE").execute()["values"]
    for i, row in enumerate(vals):
        if "<품목명>" in " | ".join(row):
            print(sh, i + 1, row[9], row[11])   # 9=금액, 11=기안일
```

세금계산서 합계와 **정확히 같은 금액**의 행이 정답이다. `--sheet-name` 지정 재실행으로
오매칭이 고쳐질 때가 있지만 보장되지 않으므로 대조는 직접 한다.

## 3. 세금계산서 글자 분리 오독 → 추출값을 믿지 않는다

일부 국세청 PDF는 텍스트가 **글자 단위로 쪼개져** 저장된다. 예:

```
공급가액  554,900,054,900   ← 같은 숫자가 두 번
세  액   49,000            ← 실제는 이 값
작성일자  2026 09 22       ← 흩어져 있음
```

추출기가 이 상태에서 공급가액을 `합계-세액`으로 보정하며 **잘못된 값**을 만들 수 있다.
판단 기준: **세액/공급가액이 4~16% 밖이면 추출이 깨진 것**이다.

```
⚠ 세액 비율 이상: 세액/공급가액 = 3.4%
```

이 경고가 뜨면 dry-run의 금액·날짜를 신뢰하지 않는다. PDF 텍스트를 직접 읽어
공급가액·세액·합계·작성일자·품목을 눈으로 확인하고 그 값을 쓴다.

## 4. 부가세 미표기 건

`합계금액`만 있고 세액이 없으면 **임의로 10%를 가산하지 않는다**. 합계를 그대로 쓴다.

## 4-1. 지급신청 메일 본문 — 고정 형식, 회신 절차 없음

지급신청 메일 본문은 **아래 4행 그대로** 쓴다. 사용자 지정 형식이며, 표·품목 목록·총액·
시트 행·첨부 목록·회신 요청 문구를 넣지 않는다. 지급신청은 회신 절차가 없기 때문에
본문이 길어질 이유가 없고, 그 정보는 전부 제목과 첨부에 이미 있다.

```
안녕하세요, 연구지원부의 홍길동입니다.
첨부 화일의 건에 대해 지급신청을 요청드립니다.
감사합니다.
홍길동 드림
```

- plain-text 단독(`msg.set_content()`) — `add_alternative(html)` 을 넣지 않는다. 표를 넣으려고
  HTML을 얹는 순간 본문이 복잡해지고 어떤 클라이언트에서 표가 깨지는지 예측할 수 없다.
- 마지막 줄에 개행을 붙이지 않는다(표시상 불필요한 빈 줄).
- 부서명은 바뀌면 한 곳만 고치도록 상수로 둔다(`DEPARTMENT_NAME`).

## 5. 금액·날짜의 출처

- 제목 금액 = 세금계산서 `합계금액`
- 시트 `기안일` = 세금계산서 **작성일자**

파일명 날짜나 인쇄 발행일을 대신 쓰지 않는다. 예: `20260813_Reagent-A…` 파일인데 세금계산서
작성일자가 2026-10-01이면 기안일은 2026-10-01.

합계 추출 정규식( fragile ):
```python
lines = [l.strip() for l in page_text.splitlines() if l.strip()]
for line in reversed(lines):
    if re.fullmatch(r"[\d,]{5,}", line):
        return line        # '이 금액을 ( 청구 ) 함' 다음 마지막 숫자 토큰
```

## 6. 실실행 후 검증

```bash
python scripts/apply_payment_skill.py "<품목명>" --folder "Y:/" --project-code <코드>
```

생성된 초안과 시트를 **다시 읽어** 확인한다:
- Gmail `drafts.list` → 제목·To·첨부 4종
- Sheets `values().get` → 기안일 값

기안일이 이미 채워진 행은 `--force` 없이는 "검증없음"으로 걸린다. 이건 버그가 아니다
(이중 기안 방지).

**`drafts.list` 가 빈 목록을 보여도 실패로 단정하지 말 것.** 스크립트는 초안 생성에 성공했고
로그에 Draft ID를 찍는다. `drafts.list` 가 0건이어면 바로 `drafts.get(<id>)` 로 해당 초안을
직접 열어 존재를 확인한다. 그게 성립하면 저장은 성공한 것이고, Gmail 임시보관함 UI 정리
때문에 목록에서 안 보이는 것일 뿐이다. 목록이 비었다는 이유로 "안 들어갔다"고 보고하지
말 것.

## 6-1. 폴더·경로를 다시 확인하기

같은 이름의 문서가 `Y:\` 루트와 `Y:\ongoing\` 에 동시에 있을 수 있다. 사용자가 지정한 경로가
그대로 작업 대상이다. 다른 폴더에 있으면 스크립트는 그쪽을 본다. 폴더를 옮겨 두었다면
스크립트 실행 전에 실제 존재 위치를 먼저 확인한다.

## 7. 파일명 대소문자

4종 세트 탐색은 glob 기반이라 `.PDF`/`.pdf` 혼용도 잡지만, 첨부를 직접 붙일 때는
`os.path.isfile` 을 먼저 확인하고 없으면 glob으로 대체한다. `전자세금계산서.PDF`(대문자) 같은
케이스가 실제로 있다.

## 8. 홈택스 HTML 파일명 = 거래명세서 stem 이 아닐 수 있다

`hometax_export.py`는 입력 HTML 파일명으로 거래명세서 기준값을 조립한다. Gmail 메시지 ID로
저장한 HTML(`1a0fb292579ce880_a.html`)은 조립이 실패해 `기준=missing` → 전건 실패한다.
**그럴 때는 기대값을 직접 준다:**

```json
{
  "1a0fb292579ce880_a": {"supplier": "라이프사이언스", "total": 4150300,
                          "items": ["Enzyme L", "CAT-0004"]}
}
```

```
HOMETAX_PIN=<핀> python scripts/hometax_export.py --src <HTML폴더> --expect-json expect.json --pin <핀>
```

`--pin` 플래그만 주고 환경변수를 빠뜨리면 `PIN 미설정(HOMETAX_PIN)` 로 전건 실패한다.
