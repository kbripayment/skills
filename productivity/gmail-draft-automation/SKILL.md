# Gmail 초안 자동화 (Sheets 행 → 초안)

Google Sheets의 특정 행 집합을 근거로 Gmail 초안을 만들고, 처리가 끝났음을 시트 마커 행으로 남기는
작업군. 대상: 견적 요청, 지급신청, 결재 요청 등 "시트 행 → 메일 초안 → 시트 상태 갱신" 형태.

## Always-on 규칙

- **발송 금지.** 초안만 만든다. `users().messages.send()`는 사용자가 별도로 명시 승인한 경우에만.
- **기존 초안을 함부로 삭제하지 않는다.** 이름이 겹칠 위험이 있으면 삭제 대신 건너뛰기(skipped)로 보고한다.
- **시트 쓰기는 초안 생성 성공 확인 뒤에만.** 초안이 안 만들어진 행의 상태를 갱신하면 시트가 실제 업무 상태와 어긋난다.
- **모든 Gmail 쓰기 후 read-back으로 검증한다** (`drafts.get(format="full")` → 수신자·제목·첨부 목록 비교). 불일치 시 성공으로 보고하지 않는다.
- **생성 여부는 `drafts.get(userId="me", id=<draft_id>)` 로 확인한다.** `drafts.list()` 은 초안을 만든 직후 0건을 반환하는 구간이 있다. list 가 비었다는 사실만으로 "미생성" 결론 내리지 않는다 — 사용자가 실제 Gmail 화면에서 보았다고 확인할 수도 있다.
- **초안을 만들 때 수신자(To)를 비워 두지 않는다.** Gmail은 `To` 헤더가 비면 400 `Invalid To header`로 거부한다. 수신자 이메일을 끝까지 못 찾았으면 본인 주소(`account@example.com`)를 To에 넣고 본문 상단에 `[수신자 미상]` 경고를 넣되, **본문이 "미상" 문구로 시작하지 않게** 한다. 발송 전 To를 직접 지정하도록 안내한다.
- **정확한 금액을 임의로 만들지 않는다.** 세금계산서에 부가세 세액이 표기되지 않은 건은 합계금액을 그대로 쓰고, 10%를 임의 가산하지 않는다. 그 사실을 본문이나 로그에 남긴다.
- **거래명세서가 여러 페이지면 페이지별 도장 날짜가 다르다.** 날짜가 다른 건을 같은 업체 초안 하나의 품목 목록으로 묶는다 — 업체 결제는 날짜별로 쪼개지 않는다. 제목에 날짜를 나열한다(`[결제] 9/22, 9/28 입고품목에 대한 ...`).
- **이미 결제요청을 보낸 적이 있어도 신규로 요청할 수 있다.** 같은 업체의 과거 결제요청 스레드가 검색돼도, 대상 날짜 건이 포함되지 않으면 다시 요청해야 한다. 메일 검색은 `subject:결제 "업체명"` 이 0건이면 발신자 도메인(`from:업체도메인`)과 날짜 구간을 넓혀 재검색한다.
- **판단 근거를 스킬 문서에 적을 때 개별 사안을 넣지 않는다.** 버그의 본질(어떤 코드가 왜 잘못되는가)과 회귀 기준(어떤 조건이 성립해야 하는가)만 쓴다. 특정 파일명·금액·시트 행을 요구사항 문서에 넣으면 다음 수정자가 "이 요구사항이 어디서 왔는지" 추적하지 못한다. 개별 데이터는 세션 중 보고서로 전달한다.

## 절차

### 1. 마커 스코프 산출
완료 마커 행(`-- <작업> 완료 -- (날짜, 배치: QB...)`)을 찾아 그 **이후** 행만 처리한다.

- 마커는 배치 번호를 포함하므로 문자열 전체를 정확히 비교한다. 날짜만 비교하면 다른 배치와 섞인다.
- 마커 행 자체와, 첫 셀이 `--`로 시작하는 어떤 행이든 데이터가 아니므로 건너뛴다.
- 마커 이후 유효 데이터 행이 하나도 없으면 **새 마커를 추가하지 말고 종료한다**(빈 배치 마커가 다음 실행을 건너뛰게 만든다).
- 시트 이름은 정확히 지정한다. `그룹과제_예시`이 아니라 `그룹과제_예시 (예시)`처럼 실제 탭명.

### 2. 열 매핑은 헤더로
시트는 열 위치가 이례적이다(`f | 요청자 | 제조회사 | Cat. No | 제품명 | 규격 | 수량 | Comment | 단가 | 금액 | Vendor | ...`).
고정 인덱스 대신 헤더 행을 읽어 이름 → 인덱스를 매핑한다. 헤더에는 공백이 섞인 이름(`단   가`)도 있다.

### 3. 수신자 수집
`업체정보` 시트에서 이름 + 이메일이 모두 있는 행만 쓴다. 이메일 없는 업체는 조용히 건너뛰고 제외 수를 보고한다.

### 4. HTML 테이블 본문
사용자 지정 열 순서를 그대로 지킨다. 일반적으로 `No. | 제조회사 | Cat. No. | 모델품목명 | 수량 | 단가 | 품목별 금액`.
규격이 있으면 품목명 아래 `<br><small>규격: ...</small>`, 빈 값은 `-`, 숫자는 천단위 콤마 + `원`.
본문은 `"하기 품목에 대한 견적 요청드립니다"`로 시작하고, 하단에 단가·합계·유효기간·배송비·세금 구분
요청 문구와 "자동 생성된 ... 초안입니다"를 넣는다. 요청자 이름은 본문에 넣지 않는다.

### 4b. 회신 절차가 없는 메일(지급신청)은 짧게
**지급신청처럼 회신 절차가 없는 메일은 위 HTML 테이블 방식을 쓰지 않는다.** 표·품목 목록·총액·시트 행·첨부 목록을 본문에 반복하면 이미 제목과 첨부에 있는 정보의 중복이다. plain-text 4줄만 쓴다:

```
안녕하세요, 연구지원부의 홍길동입니다.
첨부 화일의 건에 대해 지급신청을 요청드립니다.
감사합니다.
홍길동 드림
```

- 부서명은 상수로 분리해 한 곳에서만 바꾼다.
- 마지막 줄에 개행 붙이지 않는다(표시상 빈 줄 생김).
- `msg.add_alternative(html)` 을 넣지 않는다 — plain-text 단독.
- "복잡하게 하지 말라"는 지시가 있었으므로, 여기에 표나 요약을 덧붙이지 않는다.

### 5. 제목
`[작업유형][QB{YYYYMMDDHHMMSS}] 실험실 - {업체명}` 형식을 `email.header.Header(subject, 'utf-8')`로 RFC 2047 인코딩한다.

### 6. 초안 생성 후 마커 추가
`-- <작업> 완료 -- (YYYY-MM-DD, 배치: QB...)`를 **마지막 데이터 행 바로 다음 행** A열에 RAW로 쓴다.
같은 배치에서 일부 업체가 생성 실패하면 마커를 전체 대상으로만 기록할지 사용자에게 확인한다.

## Pitfalls

- **`drafts.list(q='subject:"한글제목"')`은 신뢰하지 않는다.** RFC 2047로 인코딩된 제목에서는 매칭이 놓쳐 빈 결과가 나온다. `drafts.list()`을 `pageToken`으로 끝까지 돌려 각 초안 헤더를 직접 읽고 디코딩해 비교한다.
- **`drafts.get(..., metadataHeaders=[...])`는 `TypeError`.** `googleapiclient`는 이 인자를 받지 않는다. `format="full"` 또는 `"metadata"`만 쓰고 헤더는 `payload["headers"]`에서 직접 필터한다.
- **첨부 초안은 36,700,160 바이트 제한에 걸린다.** `MediaUploadSizeError`가 떨어지는 원인은 개별 첨부가 아니라 메시지 전체 크기다. OCR 파이프라인을 돌리기 전에 `os.path.getsize()`로 먼저 판단한다. 해결책은 `references/gmail-draft-attachment-limits.md` 참조.
- **제목 디코딩**: `re.match(r'=\?utf-8\?B\?(.*?)\?=', value)` → `base64.b64decode` → utf-8.
- **`-c` 인라인 파이썬에서 Windows 드라이브 경로를 이스케이프하지 말 것**(`Y:\`가 문자열 종료로 파싱되어 SyntaxError). 임시 `.py` 파일로 작성해 실행한다.
- **백그라운드 실행은 `python -u`.** 버퍼링 때문에 종료 시점 전 로그가 디스크에 안 남는다.
- **시트 쓰기 전 재확인.** 마커 행 추가는 되돌리기 어려운 부작용이므로, 대상 행과 배치를 출력해서 먼저 보여준 뒤 쓴다.
- **스크립트가 잡은 시트 행을 그대로 믿지 않는다.** 자동 매칭은 OCR/LLM이 타임아웃으로 소실되면 파일명 토큰으로만 시트를 훑어 무관한 행을 집을 수 있고, `--sheet-name`을 지정해 재실행해도 다른 잘못된 행이 잡힐 수 있다(시트 지정은 해결책이 아니다). 확정 전에 세 가지를 직접 대조한다: (1) 선택 행의 `Cat. No`/`제품명`이 해당 거래명세서 품목과 일치하는가 (2) 블록 행합계가 세금계산서 합계와 일치하는가 — `행합계 0원`은 절대 성공이 아니다 (3) 공급자가 미추출 상태로 확정되지 않았는가. 하나라도 어긋나면 초안·시트 모두 손대지 말고 시트를 품목명+금액으로 직접 훑어 정답 행을 찾는다.
- **세금계산서 합계는 마지막 줄에 단독 출력된다.** 국세청 서식은 `이 금액을 ( 청구 ) 함` 다음 줄이 합계다. `청구\) fun\s*([\d,]+)` 정규식은 실패한다. 비어 있지 않은 줄을 뒤에서부터 훑어 `[\d,]{5,}` 완전 일치하는 첫 줄을 쓰고, 못 찾으면 `"금액미확인"`으로 표기한다(제목에 빈 문자열 금지).
- **시트 기안일에는 파일명 날짜가 아니라 세금계산서 작성일자를 쓴다.** 둘은 다를 수 있다(예: 파일명 8/13, 세금계산서 10/1). 헤더가 없는 시트에서는 `기안일`만 기록되고 `지급상태`/`마지막처리일시`는 건너뛰는 것이 정상일 수 있으니, 쓰기 전 헤더 존재를 확인한다.
